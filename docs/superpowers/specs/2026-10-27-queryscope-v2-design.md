# QueryScope v2 설계

사용자 요청 1~6을 순서대로 수행한다. 현재 main 7fbdd31, 코드 CI 714600f 성공. v1 원시 결과/저장 응답은 그대로 보존하고 v1의 24개 질의는 개발용으로 전환한다. 별도 18상품/24질의와 평가 기준을 먼저 커밋한다.

선택: 기존 BM25를 유지하고 관측 기반 질의 보강과 원문 발췌를 추가한다. 단순 동의어 키워드 추가는 무힌트 관측을 활용하지 못하고, 새 임베딩/모델을 도입하면 비용과 별도 캐시 검증이 필요하므로 이번 무료 범위에서는 채택하지 않는다. 질의별 하드코딩/정답 라벨 기반 검색은 금지한다. 결과가 낮으면 그대로 남긴다.

현재 문제: ExplanationService.context는 query+problem으로 지식을 먼저 검색해 실제 토큰·버려진 품사·상품 원문과 색인의 차이를 사용하지 않는다. 긴 문서도 앞400자만 가져온다. 새 Observation builder는 SearchEngine과 입력만 받아 표면형/토큰/원문 부분일치/가까운 표기/문자체계 신호를 수집한다. 검색용 일반 원칙 문구로 보강하되 원인으로 단정하지 않는다. API와 평가가 같은 builder를 사용한다. legacy 경로를 명시적으로 남겨 이전 평가 재현을 보존한다.

LLM: 기존 Responses API 어댑터와 기본 예산0 유지. 고정12개×2조건=24회 준비물을 만든다. 명시적 승인 파일+정확한 준비물 해시+--live 없이는 호출 금지. 재시도 없음, 오류도 예약 소모, 별도 결과/원장. 정상·불명·근거부족·범위밖에는 보류+무패치 기준, 실패 후보에는 가설 라벨 일치와 실제 정확도를 구분한다. 의미적 타당성은 독립 인간 검토 대기.

실패 수정: 카페트/초콜렛/워시의 토큰·순위·문서를 비교하고 명시적 후보만 엔진 사본에서 검사. 기존36+v1개발24와 별도18새순위질의의 영향 기록. 기존 잘못된 응답은 변경하지 않고 스키마/지식/프롬프트에서 보완 가능한 부분만 수정한다.

데모: 기존 재생/v1비교 보존, v2비교 화면 추가. 공개 접속 재시도 및 제한 기록, 로컬 데스크톱/모바일 검사. 새 결과 뒤 README/자소서/포트폴리오 갱신. 유료API0, 독립 인간평가 미완료, 실제 고객 일반화 미확인.
