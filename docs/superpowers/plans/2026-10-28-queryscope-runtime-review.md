# QueryScope 남은 검증과 지원 문서 업데이트

## 목표와 승인 범위

사용자의 2026-10-28 요청에 따라 남아 있는 인용 출처 혼동과 실행 불가능한 수정 후보를 보완하고 자기소개서·포트폴리오를 갱신한다. 기준 커밋은 `f7441a0`이다. 기존 프로젝트·스택·평가 기록을 유지하는 후속 수정이며 새 제품 설계는 추가하지 않는다.

## 원인과 구현 결정

현재 모델 입력의 상품 `doc_id`와 운영 문서 `id`가 모두 'supplied doc IDs'로 읽힐 수 있다. 운영 문서 본문만 인용할 수 있다는 규칙과 허용 ID를 런타임 입력에 명시한다. 모델이 제안한 연결의 표준형이 실제 색인에 없거나 분해 대상이 현재 색인 토큰이 아니면 실행 전에 차단한다. 문자열 유사성은 의미적 동의성을 증명하지 않는다.

기존 형식 검사를 완화해 과거 응답을 성공으로 바꾸는 방법은 원자료 보존 요구에 맞지 않는다. 런타임 계약을 버전으로 구분하고 기존 준비물·프롬프트·원래 24응답·일차 판정을 바이트 단위로 보존한다. 새 평가의 성격은 저장 응답에 대한 개발용 사후 검사다.

## 작업

1. `rag/runtime_contract.py`와 `tests/test_runtime_contract.py`: 허용 인용 ID, 알 수 없는 출처, 원문 변형, 존재/부재 표준형, 복합어 대상, 무관한 패치 대상의 RED→GREEN을 확인한다. `openai_provider.py`와 `explanation_service.py`에 최소 통합한다. 과거 컨텍스트의 요청 payload는 동일해야 한다.
2. 저장 응답 24건을 새 런타임 검사와 비교하는 무료 오프라인 보고서를 생성한다. 기존 일차 판정, 새 사후 판정, 실제 검색 효과, 인간 의미 평가 대기를 별도 필드로 둔다. 과거 자료 해시 보존과 후보별 기존36·새16 정답질의 회귀를 확인한다.
3. 사람이 바로 검토할 수 있도록 24건의 원응답·근거·검토 질문을 정리한다. AI 검토 의견은 AI 의견으로 표기하며 인간 평가표는 채우지 않는다.
4. 새 확인 범위를 보여 주는 정적 결과 화면과 README, 자기소개서4항목, 포트폴리오9항목, 수정 기록을 갱신한다. 모든 수치는 실제 실행 산출물에서 가져온다. 문서는 PDF와 편집 가능한 형식으로도 제공한다.
5. 전체 pytest, 검색 품질 게이트, 과거 재현·보존 검사, 데스크톱/모바일 화면 검사를 수행한다. 독립 코드 검토 후 원격 CI를 확인하고 기존 Render 정적 서비스에 반영한다.

## 고정 제약

- 추가 유료 API 호출 0회. 기존 승인/예산/원격 실행 표식/실행 워크플로는 변경하지 않는다.
- 독립 인간 의미 평가와 실제 채용 데이터·장기 운영을 완료로 표시하지 않는다.
- 과거 v3 자료는 이 보완의 개발 자료이며 새 모델 정확도나 독립 일반화 성과로 표현하지 않는다.
- 기존 `ko-search-clinic` 저장소는 변경하지 않는다.
- 새로운 개인정보·학력·경력·고객 성과를 만들지 않는다.

## 검토 중점

정상 검색을 결과 수만으로 확정하지 않는지, 인용 검사를 완화하지 않는지, 런타임 입력이 과거 준비물의 해시를 바꾸지 않는지, 실행 전 차단이 정당한 연결 후보를 과도하게 막지 않는지, 정적 화면에서 과거 일차 판정과 새 사후 검사가 혼동되지 않는지 확인한다.
