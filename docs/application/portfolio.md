## 개발 배경

검색 실패를 수정할 때에는 원인 진단과 변경의 영향 범위를 함께 확인해야 합니다. 검색 결과가 없더라도 표기 차이, 형태소 분해, 복합어 처리에 따라 필요한 수정이 다릅니다. 또한 동의어와 분석기 규칙은 여러 질의에 함께 적용되므로, 한 질의를 개선한 변경이 다른 질의의 검색 순위나 정확도를 낮출 수 있습니다. 이 프로젝트의 목표는 수정안을 제안하는 단계부터 적용 여부를 판단하는 단계까지 재현 가능한 절차로 연결하는 것입니다.

이를 위해 형태소·검색 결과·운영 지식을 함께 제공해 LLM이 원인과 후보를 제안하도록 하고, 인용 근거 검사와 실제 검색 평가를 분리했습니다. 원문을 인용했다는 사실만으로 처방의 효과가 입증되지는 않기 때문입니다. 후보를 검색 엔진 사본에 적용한 뒤 목표 질의의 개선, 다른 질의의 성능 저하, 전체 평균 변화를 확인해 채택 여부를 결정합니다.

상품 카탈로그 72건과 기존 평가 질의 36건은 직접 작성했습니다. v1의 24개 질의는 이번 개선에 사용해 개발용으로 전환했습니다. v2 당시 별도 18상품·24질의의 정답과 기준을 실행 전에 고정했지만 새 분석 어휘93개 중15개는 기존과 겹칩니다. 같은 작성자·상품 도메인·운영 지식과 실패 지식을 공유하므로 완전한 독립 평가셋은 아닙니다. v3에서는 v2도 개발용으로 전환하고 16상품·24질의를 새로 고정했습니다. 새 어휘78개 중19개가 기존90상품과 겹칩니다. 실제 고객 로그에서 발견한 문제나 알바천국의 검색 성능을 검증한 프로젝트도 아닙니다.

## 개발 범위

서비스 방향·검증 범위를 정하고 Codex를 활용해 진행한 개인 프로젝트입니다. 코드 작성·수정, 실험 자동화, 문서 정리에 Codex의 지원을 받았습니다.

ko-search-clinic의 main이 아닌 RAG 서비스와 검증을 포함한 PR #2의 최신 커밋 `493935f6`에서 새 저장소로 이어받았습니다. 전체 Git 이력과 기준 태그 `upstream-pr2`를 보존하고 기존 저장소는 변경하지 않았습니다. 기존 검색 엔진·회귀 게이트·실제 API 24회 응답을 유지하면서 새 평가 분리, 수동 수정 후보, 설명 평가 기준, 데모와 운영 검증을 보완했습니다.

BM25와 GPT-5.4-mini를 사용한 실제 생성 실험은 PR #2의 과거 기록입니다. QueryScope의 새 실험에서는 추가 유료 API를 호출하지 않았습니다. 과거 Claude·임베딩·Elasticsearch 실험도 별도 보존 문서로 구분합니다.

## 검색 진단

질의와 관찰 내용을 입력하면 형태소, 검색 상위 결과, 관련 운영 문서를 모읍니다. v2에서는 실제 분해 토큰·버려진 품사·상품 원문과 색인의 차이·자모 유사 표기·문자 체계를 지식 검색에 활용합니다. 서로 다른 관측의 문서를 확보하고 긴 문서의 관련 부분을 최대400자의 연속 원문으로 발췌해 원문 위치를 남깁니다. 관측 신호는 가설이지 확정 원인이 아닙니다. v3에서는 실제 질의 토큰이 문서에 모두 있는지를 비교해 정상 접미 표현을 복합어 누락으로 오해하는 문제를 보완했습니다. 과거 v2 계산 경로도 보존했습니다. 생성 입력에는 검색용 원인 키워드나 평가용 정답표를 넣지 않고, 관측과 운영 문서 상위3개를 제공합니다.

문서는 프로젝트에서 작성한 운영 지식입니다. 문서 ID와 본문을 대조하고, 연속 공백·줄바꿈과 짝이 맞는 강조 기호의 차이는 비교용으로 정리한 뒤 원문 위치에 대응합니다. 단어 경계와 문장부호를 바꾼 인용, 없는 출처, 잘못된 수정 규칙은 적용 경로에서 차단합니다. 인용이 맞더라도 설명의 의미적 타당성이 자동으로 보장되는 것은 아닙니다. 원인 분류·인용 추적·의미적 지지·수정 구조·수정 효과를 나눈 평가 기준을 만들었고, 자동 확정할 수 없는 의미 판단은 `requires_human_review`로 표시합니다. 기존 24개 응답의 독립 인간 의미 평가는 아직 수행하지 않았습니다.

## 수정안 검증

동의어 연결, 사용자 사전 등록, 복합어 분해를 수정 후보로 다룹니다. Pydantic 검사 후 기존 36개 질의를 다시 평가합니다. 표적 질의의 nDCG 개선, 다른 질의의 nDCG·정밀도·재현율 저하, 전체 평균 nDCG 변화를 함께 확인하고 통과한 후보만 별도 세션에 적용합니다. 이 기준은 작성한 평가셋 안에서의 적용 조건이며, 평가셋 밖의 무회귀를 보장하지 않습니다.

**PR #2의 과거 실제 응답:** 사후 재검증한 후보 6건 가운데 4건은 채택되고 2건은 기각됐습니다. ‘아답터’와 ‘백팩’은 사용자 사전에 등록하는 것만으로 검색이 개선되지 않아 반영하지 않았습니다. 각 후보는 새 세션에서 검사했으며 누적 성능 수치가 아닙니다.

| 질의 | 검색 순위 점수 전 → 후 (nDCG) | 판정 |
|---|---|---|
| 도너츠 | 0 → 1.0000 | 채택 |
| 블루투스 스피커 | 0.5000 → 1.0000 | 채택 |
| 핸드폰 | 0 → 0.5364 | 채택 |
| 케잌 주문 | 0 → 1.0000 | 채택 |
| 아답터 / 백팩 | 각각 0 → 0 | 기각 |

nDCG는 관련 상품이 검색 결과의 앞쪽에 나오는지를 평가하는 지표입니다. 이 평가에서는 1에 가까울수록 좋으며, 위 수치는 각 질의의 개별 결과입니다.

**v1에서 검증한 수동 후보:** 아답터·백팩은 사전 등록만으로 카탈로그의 어댑터·배낭 표현과 연결되지 않았습니다. 운영자가 지정한 표준형 연결을 함께 적용해 두 질의가 각각 0에서 1로 개선됐고, 각 후보는 기존 36질의 게이트를 통과했습니다. 두 후보를 함께 적용한 기존 36질의 평균은 0.5839에서 0.6395로 바뀌었습니다. 모델이 새 수정안을 발견한 성과로 계산하지 않습니다.

잘못된 `[티슈, 티슈]` 복합어 원후보는 계속 차단했습니다. 별도의 수동 후보인 물티슈→물+티슈는 0에서 1로 개선됐고 기존 게이트를 통과했지만, v1의 20질의 결합 설정에는 포함하지 않았습니다. 백팩의 원인 분류 오류, 원문 어미를 바꾼 인용, 문서 제목을 본문처럼 인용한 사례도 미해결 기록으로 남겼습니다. 운영 지식의 NR 품사 제거 설명은 실제 코드와 달라 IC/NR을 구분하도록 수정했습니다.

카페트·초콜렛·워시도 각각 분석했습니다. 카페트는 카펫과 표준형 연결, 초콜렛은 초콜릿과 연결, 워시는 바디워시의 부분어 분해로 보완했습니다. v1 설정 대비 거실 카페트는 0.8262→1, 초콜렛 선물은 0.4582→0.9832, 워시는 0→1이었고 기존36+개발20 질의 게이트를 통과했습니다. 초콜렛 선물의 무관한 향초 결과는 남겼습니다. 결합 설정에서도 측정한 순위·정밀도·재현율 하락은 없었지만 평가셋 밖의 안전성을 보장하지 않습니다.

## 실험과 결과

**PR #2의 기존 실제 생성 실험:** 12개 사례×운영 지식 제공/제거, 총24회 응답을 확보했습니다. 원인 힌트가 있는 관찰 문장을 제공했으므로 무힌트 문의의 진단 정확도로 해석하지 않습니다. 토큰 사용량 추정 비용은 약$0.03, API 지연 중앙값1.39초·p95 2.67초였으며 검색·회귀 검사를 포함한 전체 시간은 아닙니다.

최초24건 중12건이 차단됐습니다. 표시 형식 비교를 보완한 뒤 같은 저장 응답을 재검증해 인용·형식 통과6건·보류12건·차단6건을 확인했습니다. v2에서도 이 상태 분포는 동일했습니다. 새로운 모델 성능이 아닌 사후 검증이며 원응답을 변경하지 않았습니다.

**v1에서 개발 자료로 전환한 24질의:** 당시 사전 고정한 정답있는20질의의 평균 nDCG@10은 아답터·백팩 수정으로 0.8255→0.9142였습니다. 이번 추가 세 후보를 적용한 개발 결과는 0.9142→0.9992입니다. 두 시점의 결과를 독립 평가로 중복 계산하지 않습니다.

**v2 별도 작성 자료:** 새로운18상품·24질의를 구성하고 정답·프로토콜을 Git 커밋과 SHA-256으로 고정했습니다. 실행 전 중복 검사에서 기존 질의1개를 발견해 교체하고 다시 고정한 이력도 남겼습니다. 새로운24개에는 5계열의 원인 가설15개, 정상3개, 원인 불명2개, 근거 부족2개, 범위 밖2개가 있습니다.

| 근거 hit@3 | 힌트 기존 → 보완 | 무힌트 기존 → 보완 |
|---|---|---|
| v1 개발11개 계열 가설 | 11/11 → 11/11 | 1/11 → 10/11 |
| 새15개 계열 가설 | 9/15 → 11/15 | 6/15 → 10/15 |

같은 질의·카탈로그·상위 문서 수·판정 기준을 유지하고 관찰 문장의 힌트 유무만 바꿨습니다. 새 무힌트 조건에서 표기 변형3/3, 영한 혼용3/3, 유의어2/3, 분해 오류0/3, 복합어2/3이었습니다. 유의어는 기존3/3에서 하락했습니다. 휴대용의 정상 분석을 부분어 누락으로 취급해 복합어 문서가 밀고 들어온 사례를 남겼습니다.

분해 오류로 작성한 멀티텝·악세사리는 실제로 단일 토큰이며, 피펫트는 분해돼도 관련 문서가 이미1위였습니다. 차단제도 이미 정상 검색됐습니다. 작성 가설과 실제 원인은 같지 않았고, 전등의 관련도 정답에도 모호성이 있었습니다. 고정 정답을 사후 변경하지 않았으며 독립 사람의 검토가 필요한 한계로 기록했습니다. 근거 검색 점수를 모델 진단 정확도로 표현하지 않습니다.

같은 수동 수정 설정을 새 카탈로그에 적용해도 정답있는18질의 평균 nDCG@10은 **0.5351→0.5351**, 개선0·하락0이었습니다. 기존 사례의 사전 수정이 새로운 표기를 자동 해결하지 못한 결과입니다. 관련 문서 없는6개는 순위 평균에서 제외하며 결과 유무를 보류 성능으로 계산하지 않습니다.

**v3 후속 검증:** v1·v2를 개발용으로 전환하고 별도16상품·24질의·정답·분석기 구성을 실행 전 커밋과 해시로 고정했습니다. 정상8개는 정답1위, 통제된 부분어 누락4개는 원문 존재·토큰누락·검색0건·분해후복구를 평가 전에 검사했습니다. 통짜 색인을 강제한 합성 결함이며 자연 발생 고객 장애가 아닙니다.

새 정상8개의 잘못된 누락 신호는 양조건에서 **8/8→0/8**이었습니다. 새8개 계열의 무힌트 hit@3은 **7/8→7/8**, 힌트는8/8→8/8로 개선되지 않았습니다. microscope의 무힌트 근거 검색 실패를 남겼고 분해 오류 계열은n=0입니다. 개발자료 유의어는2/3→3/3으로 복구됐지만 새 평가 성과로 합산하지 않았습니다.

통제된 분해 수정4개로 정답있는16질의 평균 nDCG@10은0.5000→0.7500, 측정 지표 하락0이었습니다. 구성에 사용한 원인을 되돌린 수동 실험이며 자동 수정안 발견이 아닙니다. 팔래트·파스탤·microscope·박자기의 검색 실패는 남았습니다. v2의 검색·순위·수정·과거 응답 재검증 결과는 동일하게 재현했습니다.

추가 유료 호출 없이 실제 LLM 평가 준비까지 완료했습니다. v3 고정12개×힌트유무24회의 정확한 입력·예산·검토표와 승인 확인 코드를 마련했습니다. 새 모델 응답은0건이고 진단·보류 성능은 미실행입니다. 실제 호출 후에도 원인 가설 일치, 인용 추적, 의미적 지지, 수정 구조, 실제 효과를 나눠 기록하도록 구성했습니다.

## 사용 화면

[공개 저장 결과 데모](https://queryscope-zwia.onrender.com/)에서 A04 핸드폰의 관측·인용·채택 결과와 A01의 인용 검증 차단을 확인하는 흐름을 제공합니다. 기록을 JSON으로 내려받을 수 있습니다. [v3 평가 비교](https://queryscope-zwia.onrender.com/evaluation-v3.html)에서는 새24질의의 입력·토큰·기존/보완 문서·원문 발췌를 비교하며, [v1 기록](https://queryscope-zwia.onrender.com/evaluation.html)은 별도로 보존했습니다.

공개 사이트는 저장된 응답과 오프라인 결과를 재생하는 정적 데모입니다. 새 생성 서버나 API 키를 배포하지 않았습니다. 공개 접속은 실행 환경의 프록시 CONNECT 403과 웹 도구 접근 제한으로 확인하지 못했습니다. Render 배포 상태와 공개 HTTP 접속·가용성을 구분해 [운영 기록](https://github.com/sokldjs554/queryscope/blob/main/docs/verification/queryscope-v3/OPERATIONS.md)에 남겼습니다.

로컬에서는 1440·320·390·650px에서 과거 응답24건·새 평가24행·원문 펼침·입력 비교·가로 넘침·자료 로딩 실패를 검사했습니다. 기존 화면의 취소·오류·다운로드도 재검사했습니다. 실제 생성 경로의 브라우저 상태 전환만 테스트 응답을 사용했습니다.

로컬 전체 테스트는 **378개 통과·1개 건너뜀·2개 제외**입니다. 기본 검색 기준선 평균 nDCG 0.5839도 유지했으며 [최종 CI](https://github.com/sokldjs554/queryscope/actions/runs/40505257938)의 Ubuntu·Windows 테스트와 검색 품질 게이트도 통과했습니다. README 규모 문장 누락으로 첫 CI가 실패한 이력과 수정 후 재검증은 운영 기록에 남겼습니다. 이 결과는 모델 정확도나 공개 운영 성과가 아닌 코드·화면 검사입니다.

## 운영 설정과 한계

실제 생성은 서버에서 명시적으로 활성화하고 로컬 운영 토큰으로 접근합니다. API 키는 화면에 전달하지 않습니다. 요청 전에 비용을 예약하며 자동 재시도 없이 호출 수를 제한합니다. 요청·보류·차단·상류 오류·바쁨 응답과 최근 100회의 p95를 확인할 수 있습니다. 기존 승인 24회는 소진됐으므로 기본 호출 한도를 0으로 설정하고 종료된 유료 평가 실행 경로를 차단했습니다. QueryScope의 추가 유료 호출은 0회입니다.

실제 로컬 HTTP 검사에서 준비 이후 정적 자료·상태 조회 GET 120회는 모두 200이었고 p95는 1.822ms였습니다. 기본 생성 경로의 예상 503과 빈 입력의 422도 확인했습니다. 이 수치는 모델 추론이나 검색 계산의 지연, 공개 서비스의 SLA가 아닙니다. 오류·동시 요청·취소의 로컬 테스트도 실제 공급자 장애 실험과 구분합니다.

확인한 범위는 작성 자료의 검색 평가, 로컬 서비스·화면, CI와 Render의 정적 배포 상태입니다. 실고객 효과, 공개 생성 API의 장기 운영, 다중 서버의 집계·인증, 독립 평가셋의 일반화는 확인하지 않았습니다. 모델 학습, LangChain·LlamaIndex 사용 경험으로 소개하지 않습니다.

남은 과제는 microscope의 근거 검색 실패, 작성 가설·정답의 모호성, 새로운 상품의 미해결 순위, 자연 발생 분해 오류 평가, 독립적인 사람의 의미 평가와 실제 모델 진단·보류 성능입니다. 후속 개선에 v3를 사용한다면 이를 개발용으로 전환하고 다시 새 평가를 고정해야 합니다. 추가 생성 평가안은 GPT-5.4-mini 스냅샷·24회·비용 예약 상한$0.30이며 미승인·미실행입니다. 승인과 준비물 해시가 일치해야 실행되고 오류도 한도를 소모합니다.
