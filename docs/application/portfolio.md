# QueryScope 포트폴리오

기존 Library 포트폴리오를 읽기 전 작성한 별도 초안입니다. 기존 원문의 구성·표현 대조는 원본 파일 제공 후 진행합니다.

한국어 검색 실패를 관측하고, RAG 설명의 근거와 수정 효과를 구분해서 검증하는 Python 프로젝트입니다. [저장소](https://github.com/sokldjs554/queryscope) · [실행과 데모 안내](../../README.md) · [검증 원자료](../verification/queryscope-v1/run-v1/results.json).

## 만든 이유와 개발 범위

검색 결과가 없다는 설명만으로는 문서가 없는지, 형태소가 잘못 분해됐는지, 표현이 다른지 알 수 없습니다. QueryScope는 토큰·검색 결과·운영 지식을 함께 보여 주고, 수정 후보를 별도 세션의 회귀 검사로 연결합니다.

기존 ko-search-clinic PR #2에서 새 저장소로 분기했습니다. 기존 RAG 서비스·실제 API 24회·저장 결과를 상속했고, 이번에는 평가 분리, 실패 원인 분석, 명시적 연결 후보, 근거 판정 구분, 비용 차단, 데모·운영 검증을 보완했습니다. 전체 Git 이력과 기준 태그를 보존했습니다. Codex 지원으로 구현·실험·문서를 작성했으며 개인의 수작업 구현 비율을 임의로 주장하지 않습니다.

## 구조

Python 3.11/3.12, Kiwi 0.24.1(cong-global), BM25 검색, Pydantic 처방, FastAPI, 정적 JavaScript 화면을 사용합니다. 기존 생성 경로는 OpenAI Responses API이며 현재 기본 한도는 0회입니다. 생성 없이 저장 기록과 새 오프라인 실험을 볼 수 있습니다.

원인 분류 → 인용 추적 → 의미 검토 → 수정 구조 → 회귀 효과를 구분합니다. 인용 추적 성공은 의미적 지지의 충분조건이 아니므로 사람 검토 필요를 표시합니다.

## 확인한 개선

| 대상 | 결과 | 조건 |
|---|---|---|
| 아답터·백팩 | 사전만 0→0, 사전+표준형 연결 각각 nDCG 0→1 | 운영자가 명시한 후보, 기존 36질의 게이트 |
| 새 순위 질의 20개 | 평균 nDCG 0.8255→0.9142, 4개 개선 | 두 연결 후보 동시 적용, 측정 지표 하락 0 |
| 티슈 | 잘못된 원후보 차단, 별도 물티슈 분해 후보 0→1 | 수동 대체 후보, 신규 20질의 결합 결과에는 미포함 |

새 평가 24개는 정답·기준·해시를 실행 전에 커밋했습니다. 관련 문서가 없는 4개는 순위 평균에서 제외했습니다. 기존 어휘와 카탈로그를 재사용했으므로 완전한 독립 검증은 아닙니다.

## 실패에서 확인한 한계

신규 원인 계열 11개에서 힌트가 있을 때 근거 검색 hit@3는 11/11, 없으면 1/11이었습니다. 새 LLM을 호출하지 않았으므로 이를 원인 진단 정확도나 보류율로 표현하지 않았습니다. 거실 카페트·초콜렛 선물·워시는 여전히 순위 목표에 미치지 못했습니다.

백팩의 잘못된 원인 분류, 원문과 다른 인용, 제목 인용, 잘못된 복합어 후보를 기록했습니다. 설명의 의미적 타당성은 독립 인간 평가가 필요합니다. 기존 운영 지식의 NR 품사 제거 설명도 코드와 불일치해 수정했습니다.

## 사용성과 운영

화면에서 과거 실제 응답 재생과 새 오프라인 평가를 구분하고 입력·근거·기각 이유를 확인할 수 있습니다. 1440/320/390/650px 화면 및 오류·취소·내보내기를 검사했습니다. 실제 로컬 HTTP GET 120회에서 예상 응답을 확인했으며 준비 이후 p95는 1.937ms였습니다. 정적 자료·상태 조회의 로컬 값이며 실제 모델이나 공개 API SLA는 아닙니다.

이번 추가 유료 호출은 0회입니다. 새 생성의 원인 정확도·의미 타당성·보류율, 실제 채용 데이터 성능, 공개 생성 API 장기 운영은 후속 검증 대상입니다.
