# 알바천국 AI 개발자 지원용 자기소개서 문안

이 문안은 QueryScope의 확인된 결과를 반영한 프로젝트 중심 초안입니다. 개인 경력·학력·팀 기여를 추정해 추가하지 않았습니다. 원본 자소서가 제공되면 해당 문맥과 분량에 맞춰 반영할 수 있습니다.

## 지원동기

검색 결과를 설명하는 AI가 실제 서비스에 도움이 되려면, 설명의 근거와 수정의 효과를 따로 확인할 수 있어야 한다고 생각합니다. 한국어 상품 검색을 다루는 QueryScope에서 같은 의미의 표현이 달라 결과가 누락되는 문제를 분석하면서, 답변을 생성하는 것에서 끝나지 않고 검증 가능한 판단으로 연결하는 개발에 관심을 갖게 됐습니다. 알바천국에서도 구직자가 원하는 정보를 찾는 과정의 실패를 관측하고, 개선의 근거를 확인하는 AI 개발에 기여하고 싶습니다.

## 직무역량

기존 ko-search-clinic의 RAG 기능과 검증 이력을 QueryScope로 이어받아 Python·Kiwi·BM25·FastAPI 기반 검색 진단 흐름을 보완했습니다. 생성된 원인 분류, 원문 인용, 수정 후보를 나누고, 인용문이 원문에 있다는 사실만으로 설명의 의미를 검증했다고 표시하지 않도록 했습니다. 수정 후보는 별도 검색 엔진에서 평가하며 기본 설정을 보존합니다. 구현과 분석에는 Codex를 활용했습니다.

## 문제 해결 경험

아답터와 백팩 사례에서 사용자 사전 등록만으로는 검색이 개선되지 않았습니다. 토큰 분해를 막아도 카탈로그의 어댑터·배낭 표현과 연결되지 않는다는 점을 확인하고, 명시적 표준형 연결을 함께 검증했습니다. 두 사례의 nDCG@10은 각각 0에서 1로 개선됐고 기존 36개 질의의 회귀 게이트를 통과했습니다.

개발 사례만 다시 검사하는 한계를 줄이기 위해 새 24개 질의의 정답과 기준을 실행 전에 고정했습니다. 정답 문서가 있는 20개에서 평균 nDCG@10은 0.8255에서 0.9142로 올랐습니다. 같은 상품·어휘를 재사용한 작성 자료라 고객 데이터에서 일반화된 성능으로 해석하지 않았습니다.

좋지 않은 결과도 별도로 남겼습니다. 원인 힌트를 제거하자 신규 11개 질의의 관련 근거 검색 적중이 11개에서 1개로 줄었습니다. 이를 모델 진단 정확도와 구분하고, 원인을 뒷받침할 정보가 부족한 입력과 설명을 검토 대상으로 표시했습니다. 추가 유료 API 호출 없이 확인할 수 있는 범위와 아직 평가하지 못한 범위를 나눈 경험입니다.

## 입사 후 포부

서비스의 실제 로그와 정책을 이해한 뒤, 실패 유형과 평가 기준을 먼저 정하고 작은 변경의 효과부터 검증하겠습니다. 생성 결과의 품질뿐 아니라 근거 부족, 오류, 지연, 비용을 함께 관측하고, 자동으로 판단하기 어려운 부분을 명시해 운영자가 검토할 수 있는 AI 기능을 만들고 싶습니다.
