# 윤기혁 | 자기소개서

지원 기업: (주)미디어윌네트웍스 · 알바천국 AI 개발자

## 지원동기

알바천국의 AI 공고 비교 분석과 입사지원 메시지 작성 서비스에서 주목한 부분은, 공고와 이력서의 정보를 바탕으로 사용자의 판단과 지원에 쓰이는 내용을 생성한다는 점입니다. 공고 비교에서는 급여·근무시간 같은 조건이 정확히 대응해야 하고, 지원 메시지에서는 이력서에 없는 경험이 추가되지 않아야 한다고 생각합니다. 이런 기능의 품질을 높이려면 문장의 자연스러움과 함께 원문 정보의 누락·왜곡을 평가하는 기준이 필요합니다.

저는 ko-search-clinic의 RAG 기능과 검증 이력을 이어받은 QueryScope에서 검색 실패에 대한 LLM의 설명을 원문 근거와 대조하고, 제안한 수정이 실제 검색을 개선하는지 별도로 검사했습니다. 그 과정에서 인용 조건을 통과한 후보라도 검색 개선에는 효과가 없을 수 있음을 확인했습니다. 이 경험을 통해 생성 결과를 실제 기능에 연결하는 단계의 검증을 더 깊이 다루고 싶어졌습니다. 공고에 명시된 RAG 개발과 실험·평가, 운영 품질 개선 업무에서 이러한 경험을 발전시키며, 알바천국의 공고 비교·지원 문구 생성에 필요한 근거 검증과 기능별 평가 체계를 함께 개발하고자 지원했습니다.

## 직무역량

이러한 검증 과정을 서비스로 연결하기 위해 프로젝트의 방향과 평가 범위를 정하고, 코드 구현과 실험 자동화에 Codex를 활용했습니다. Python·FastAPI 기반의 진단 API와 점검 화면에서 형태소 분석 결과, 검색 순위, 관련 운영 문서를 연결했습니다. 기존 생성 경로는 원인 설명·실패 유형·수정 후보를 구조화된 응답으로 받도록 구성하고, 이번에는 저장 응답 재생과 새 오프라인 평가를 구분했습니다.

수정 후보는 동의어 연결, 사용자 사전 등록, 복합어 분해로 제한했습니다. 인용과 규칙 검사를 통과한 후보를 별도 검색 엔진 사본에 적용하고, 기존 36개 질의의 순위·정밀도·재현율 저하를 검사했습니다. 아답터와 백팩은 사용자 사전에 등록하는 것만으로는 개선되지 않았습니다. 토큰 분해를 막아도 카탈로그의 어댑터·배낭 표현과 연결되지 않는다는 점을 확인하고, 명시적인 표준형 연결을 함께 적용했습니다. 두 수동 후보는 각각 nDCG@10이 0에서 1로 개선됐고 기존 평가셋의 회귀 게이트를 통과했습니다.

개발에 사용한 사례와 구분해 새 24개 질의의 정답과 평가 기준을 실행 전에 고정했습니다. 관련 문서가 있는 20개에서 두 수정안을 함께 적용한 평균 nDCG@10은 0.8255에서 0.9142로 높아졌고, 측정한 순위·정밀도·재현율의 하락은 없었습니다. 다만 같은 상품과 어휘를 재사용한 작성 자료이므로, 실제 고객 데이터에서 일반화된 성능으로 해석하지 않았습니다.

## 문제 해결 경험

검증 기준 자체가 적절한지도 확인해야 했습니다. 기존 실제 API 응답에서 인용 내용이 달라진 경우와 줄바꿈·강조 표시만 다른 경우가 같은 오류로 처리되는 문제를 발견했습니다. 내용이 동일한 인용까지 막으면 검토 가능한 후보를 줄이지만, 비교 기준을 무작정 완화하면 잘못된 근거를 통과시킬 수 있었습니다.

보완한 검증기는 단어 경계와 문장부호를 유지하면서 연속 공백·줄바꿈과 짝이 맞는 강조 기호만 정리하고, 일치 구간을 원문 위치에 연결합니다. 같은 저장 응답을 다시 검사해 표시 형식 때문에 차단된 사례를 복구하되 내용이 달라진 인용은 계속 차단했습니다. QueryScope에서는 여기서 더 나아가 원인 분류, 인용의 원문 존재, 의미적 지지, 수정 구조와 실제 효과를 나눴습니다. 원문에 있는 인용도 이번 진단을 뒷받침하는지는 자동 확정하지 않고 사람의 검토가 필요하다고 표시했습니다.

좋지 않은 결과도 남겼습니다. 신규 원인 계열 11개 질의에서 상위 3개 근거 검색의 적중은 힌트가 있을 때 11개, 제거했을 때 1개였습니다. 이는 근거 검색 결과이며 새 LLM의 진단 정확도가 아닙니다. 추가 유료 호출 없이 검사했기 때문에 새 질의에서 모델이 적절히 판단을 보류하는지는 미검증으로 남겼습니다. 낮은 수치를 숨기지 않고 입력 차이와 재현 방법을 기록하면서, 확인한 개선과 아직 주장할 수 없는 성과를 구분했습니다.

## 입사 후 포부

입사 후에는 먼저 팀의 AI 기능별 입력 자료와 출력 형식, 기존 평가 기준을 익히겠습니다. 공고 비교나 지원 문구 생성 업무를 맡는다면, 팀과 함께 원문에 없는 정보의 추가, 주요 조건의 누락, 조건 간 잘못된 대응을 구분한 평가 사례를 정리하겠습니다. 프로젝트에서도 인용의 원문 일치와 의미적 지지를 구분했지만 독립적인 사람의 의미 평가는 남아 있습니다. 채용 서비스에서는 문맥과 의미가 맞는지 판단할 기준을 실제 사례와 함께 다듬어야 한다고 생각합니다.

개선안을 적용할 때에는 기존 사례와 새로 확보한 사례를 구분해 비교하고, 품질 변화와 함께 응답 시간·실패율·호출 비용을 확인하겠습니다. 오류를 입력 자료, 검색, 생성, 후처리 단계로 나눠 원인을 추적하고 실험 조건과 수정 이유를 코드 리뷰로 공유하겠습니다. 이를 통해 알바천국의 AI 기능을 추가하고 개선하는 과정에서, 변경 효과를 설명하고 반복해서 검증할 수 있는 개발자로 기여하겠습니다.
