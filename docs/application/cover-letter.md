# 윤기혁 | 자기소개서

지원 기업: (주)미디어윌네트웍스 · 알바천국 AI 개발자

## 지원동기

알바천국의 AI 공고 비교 분석과 입사지원 메시지 작성 서비스에서 주목한 부분은, 공고와 이력서의 정보를 바탕으로 사용자의 판단과 지원에 쓰이는 내용을 생성한다는 점입니다. 공고 비교에서는 급여·근무시간 같은 조건이 정확히 대응해야 하고, 지원 메시지에서는 이력서에 없는 경험이 추가되지 않아야 한다고 생각합니다. 이런 기능의 품질을 높이려면 문장의 자연스러움과 함께 원문 정보의 누락·왜곡을 평가하는 기준이 필요합니다.

저는 ko-search-clinic의 RAG 기능과 검증 이력을 이어받은 QueryScope에서 검색 실패에 대한 LLM의 설명을 원문 근거와 대조하고, 제안한 수정이 실제 검색을 개선하는지 별도로 검사했습니다. 그 과정에서 인용 조건을 통과한 후보라도 검색 개선에는 효과가 없을 수 있음을 확인했습니다. 이 경험을 통해 생성 결과를 실제 기능에 연결하는 단계의 검증을 더 깊이 다루고 싶어졌습니다. 공고에 명시된 RAG 개발과 실험·평가, 운영 품질 개선 업무에서 이러한 경험을 발전시키며, 알바천국의 공고 비교·지원 문구 생성에 필요한 근거 검증과 기능별 평가 체계를 함께 개발하고자 지원했습니다.

## 직무역량

이러한 검증 과정을 서비스로 연결하기 위해 프로젝트의 방향과 평가 범위를 정하고, 코드 구현과 실험 자동화에 Codex를 활용했습니다. Python·FastAPI 기반의 진단 API와 점검 화면에서 형태소 분석 결과, 검색 순위, 관련 운영 문서를 연결했습니다. 기존 실제 생성 응답의 재생과 새 오프라인 평가를 구분하고, 원인 설명·인용·수정 효과를 따로 확인하도록 구성했습니다.

수정 후보는 동의어 연결, 사용자 사전 등록, 복합어 분해로 제한했습니다. 아답터와 백팩은 사용자 사전만으로 개선되지 않아 카탈로그의 어댑터·배낭 표현과 명시적으로 연결했고, 두 수동 후보의 nDCG@10은 각각 0에서 1로 개선됐습니다. 이후 카페트·초콜렛·워시의 남은 실패를 분석해 표기 연결과 복합어 분해를 추가했습니다. 기존 36개 질의와 정답 문서가 있는 개발 20개 질의에서 회귀를 검사했고, 개발 20개 평균 nDCG@10은 0.9142에서 0.9992로 높아졌습니다. 초콜렛 선물에 무관한 향초가 남는 한계도 함께 기록했습니다.

개발 자료의 성과를 일반화하지 않기 위해 상품과 표현을 일부 바꾼 별도 18상품·24질의를 작성하고 정답과 기준을 실행 전에 고정했습니다. 같은 수정 설정을 적용해도 새 순위 평가 18개의 평균은 0.5351로 개선되지 않았습니다. 이 결과를 통해 특정 사전 수정의 효과와 새로운 표현에 대응하는 능력을 구분해야 한다는 점을 확인했습니다.

## 문제 해결 경험

검증 기준 자체가 적절한지도 확인해야 했습니다. 기존 실제 API 응답에서 인용 내용이 달라진 경우와 줄바꿈·강조 표시만 다른 경우가 같은 오류로 처리되는 문제를 발견했습니다. 단어 경계와 문장부호를 보존하면서 표시 차이만 정리하고, 일치 구간을 원문 위치에 연결했습니다. 이를 새 모델의 정확도 향상이 아닌 같은 응답에 대한 검증기 보완으로 기록했습니다. 인용이 원문에 있어도 이번 진단을 지지하는지는 자동 확정하지 않고 사람의 검토 대상으로 남겼습니다.

원인 힌트가 없는 입력도 따로 검사했습니다. 이전 자료에서는 관련 근거 검색이 11개 중 1개만 적중했습니다. 검색 입력에 실제 토큰과 버려진 품사, 상품 원문과 색인의 차이를 활용하고 긴 문서의 관련 부분을 발췌하도록 보완했습니다. 개발 자료는 10개가 적중했고, 별도 작성 자료의 15개 원인 계열 가설에서는 적중이 6개에서 10개로 늘었습니다.

좋지 않은 결과도 남겼습니다. 당시 새 자료의 유의어 계열은 3개 중 3개에서 2개로 하락했고, 일부 작성 원인 가설은 실제 분석 결과와 맞지 않았습니다. 후속 분석에서 정상 접미 표현을 복합어 누락으로 오해하는 문제를 확인해, 실제 분석 토큰의 색인 포함 여부를 검사하도록 수정했습니다. 이전 자료를 개발용으로 전환하고 별도 16상품·24질의의 기준을 고정했습니다. 새 정상 검색 8개에서 잘못된 누락 신호는 8개에서 0개로 줄었지만, 새 원인 계열 8개의 무힌트 근거 검색은 7개로 그대로였습니다. 통짜 색인을 강제한 누락 사례는 통제된 합성 실험으로 구분했고 실제 고객 일반화나 모델 진단 정확도로 표현하지 않았습니다. 추가 유료 호출은 하지 않고 실제 모델의 진단·보류를 비교할 입력과 실행 코드를 준비했습니다. 모델 평가와 독립적인 사람의 의미 평가는 미완료로 명시하며, 확인한 성과와 아직 주장할 수 없는 범위를 구분했습니다.

## 입사 후 포부

입사 후에는 먼저 팀의 AI 기능별 입력 자료와 출력 형식, 기존 평가 기준을 익히겠습니다. 공고 비교나 지원 문구 생성 업무를 맡는다면, 팀과 함께 원문에 없는 정보의 추가, 주요 조건의 누락, 조건 간 잘못된 대응을 구분한 평가 사례를 정리하겠습니다. 프로젝트에서도 인용의 원문 일치와 의미적 지지를 구분했지만 독립적인 사람의 의미 평가는 남아 있습니다. 채용 서비스에서는 문맥과 의미가 맞는지 판단할 기준을 실제 사례와 함께 다듬어야 한다고 생각합니다.

개선안을 적용할 때에는 기존 사례와 새로 확보한 사례를 구분해 비교하고, 품질 변화와 함께 응답 시간·실패율·호출 비용을 확인하겠습니다. 오류를 입력 자료, 검색, 생성, 후처리 단계로 나눠 원인을 추적하고 실험 조건과 수정 이유를 코드 리뷰로 공유하겠습니다. 이를 통해 알바천국의 AI 기능을 추가하고 개선하는 과정에서, 변경 효과를 설명하고 반복해서 검증할 수 있는 개발자로 기여하겠습니다.
