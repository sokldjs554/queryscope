## 실행 순서와 고정 기준
1. 이 계획·cases.json·rubric.json의 SHA-256을 manifest.json으로 기록하고 Git 커밋.
2. PR 기준 테스트와 기준 검색을 실행. 새 정답을 본 뒤 수정하거나 어려운 행을 제거하지 않는다.
3. 기존 저장 응답을 원형 보존. 아답터/백팩은 사용자 사전만 vs 사전+명시적 표준형 연결 비교.
4. 신규 질의는 빈 설정 vs 위 두 수정 동시 설정으로 nDCG@10/recall@10/P@5(분모 5)를 비교.
   정답 없는 4건은 nDCG 평균에서 제외, 결과 발생률과 보류 기대를 별도 기록.
   기존 게이트의 precision5는 min(5,반환수) 분모를 사용하므로 별도 이름으로 기록.
5. 기존 36개 전체: 기존 게이트 min gain .05, epsilon .02 유지. 새 20개는 개별 지표 하락 전부 기록.
6. 힌트/무힌트는 질의·모델·카탈로그·검색 top3·본문 400자 한도를 고정하고 관찰 문장만 변경.
   무료 실행에서는 검색 문서 ID·본문·입력 해시·계열별 근거 hit@3/MRR을 측정.
   LLM 새 생성, 원인 정확도·설명 의미·자연 발생 보류율은 not_run. 저장 답변을 새 입력의 답변으로 재사용하지 않는다.
7. 부족 근거의 보류는 검증기 계약 테스트(수작업 raw fixtures)로 검사. 실제 모델 보류 성능과 혼동 금지.
8. 설명 평가는 원인/인용 추적/의미 지지/수정 구조/수정 효과 각각 분리. 자동 의미 확정 금지.
9. 로컬 운영: 키 없이 실제 HTTP 상태/기본 live off/400계열 오류/재생 자료 접근 및 지연 측정.
   provider timeout/busy는 테스트 대역으로만 검사. 공개 운영/SLA/실사용자 부하는 미검증.
10. 새 결과를 본 후 지원 문서 작성. 유료 API 0회. 과거 24회 기록을 새 실험 성과로 합산 금지.
