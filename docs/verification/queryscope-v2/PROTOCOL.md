# QueryScope v2 사전 고정 프로토콜

작성: 2026-10-27 (한국 시각). Codex가 사용자 요청에 따라 직접 작성한 합성 상품·질의·정답. 실제 고객 자료가 아니며 독립 인간 평가 없음.

v1의 24질의는 이번 개선에 사용하는 개발셋이다. 과거 36질의/12API 사례 및 원시 응답/해시를 보존한다. 새 18상품·24질의는 별도 파일/색인으로 분리하고 실행 전에 이 파일·cases/catalog/rubric의 SHA-256을 Git 커밋한다. 평가 점수를 본 후 이 자료로 검색기를 튜닝하지 않는다. 이후 버그 수정은 근거와 전후 실행을 남긴다.

정답은 이름·설명·요청 의도에 따라 작성한 문서 ID에 관련도 2, 미기재 문서는 0으로 지정했다. 기존 카탈로그의 ID·상품 제목·질의 문자열과 중복을 검사하고 공유 공백 어휘와 분석 토큰 비율도 보고한다. 도메인은 여전히 한국어 상품 검색이며 일반 용어/운영 지식/실패 계열 및 작성자 편향은 공유한다. 새 어휘라는 사실은 독립 일반화를 보장하지 않는다.

15개 실패 후보(5계열×3)는 의도한 원인 가설이다. 자연 형태소 분석 결과를 보기 전에 작성했으므로 가설과 실제 동작이 어긋날 수 있다. 실제 관측 토큰/원문/순위와 함께 보고하고 정답을 사후 변경하지 않는다. 특히 표기 변형과 잘못된 분해는 중첩 가능하다. 근거 문서 적중은 문서 검색만 측정하며 실제 원인 정확도나 인용의 의미 타당성과 구분한다.

정상 3개, 원인 불명 2개, 근거 부족 2개, 범위 밖 2개를 포함한다. 근거 부족 2개는 양 조건 모두 운영 문서를 명시적으로 제거한다. 힌트/무힌트는 관찰 문장만 다르고 같은 질의·카탈로그·분석기·top3·본문 상한400·평가 기준을 사용한다. 힌트는 주어진 가설이지 신뢰할 수 있는 정답이 아니다. 가설을 무조건 따라가는 출력도 인간 검토 대상이다.

기존 query+problem BM25와 관측 기반 검색 개선을 동일 데이터/조건에서 비교한다. 새 검색은 질의·분석기·카탈로그에만 접근하고 qrels/family/expected_action을 읽을 수 없다. 검색어 확장과 선택 문서·본문 오프셋을 기록한다. 부분문자열·가까운 표기·분해 신호는 검색 힌트이지 자동 확정 원인이 아니다.

검색 순위: 정답 있는18질의 nDCG@10/recall@10/고정분모P@5. 정답 없는6개는 순위 평균 제외하고 결과 수만 보고한다. 기존 카페트·초콜렛·워시 수동 수정은 v1개발24 및 기존36에서 개별/결합 전후와 모든 하락을 기록한다. 새 카탈로그에도 같은 설정을 적용해 영향만 확인하며 새 정답으로 후보를 선택하지 않는다.

실제 모델 평가 준비: rubric의 고정12개×힌트/무힌트=24회. dry-run은 원본입력/해시/예산/빈 판정행만 생성하고 model_answer=null, not_run으로 기록한다. 유료 실행은 별도 사용자 승인 후 정확한 준비물 해시에 결합된 승인 파일과 --live가 모두 있을 때만 허용한다. 원응답을 즉시 저장하고 오류·비용·지연·예약을 남기며 재시도/덮어쓰기/기존 응답 재활용을 금지한다. 이번 요청은 실행 승인 아님. 승인 전 코드 준비·테스트대역 검사만 허용한다.

의미 평가는 자동 확정하지 않는다. 원인 가설 일치, 인용 추적, 사람 의미 검토, 수정 구조, 측정 효과의 다섯 축을 분리한다. 독립 사람 검토표에는 빈 판정과 역할/검토자/사유 필드를 둔다. 미실행/오류/검증차단을 보류 성공에 포함하지 않는다.
