이번 추가 유료 호출은 0회이다. 기존 승인24회와 별도 캠페인이며, 아래 계획을 알리는 것은 실행 승인이 아니다.

- 모델: `gpt-5.4-mini-2026-03-17`, Responses API, reasoning none, 구조화 JSON, tools 없음, 재시도 없음.
- 호출 수: **24회** (고정12개 × 무힌트/힌트 각1회). T01/T02/T13/T14/T15/T16/T05/T09/T17/T21/T23/T24. 원인4계열6개, 정상2, 불명1, 근거부족1, 범위밖2를 포함한다.
- 표준 단가: 입력 $0.75/1M, 출력 $4.50/1M. 2026-10-27 [공식 모델 페이지](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에서 모델 스냅샷·단가 확인. 캐시 할인 없이 계산하고 지역 전용 엔드포인트를 사용하지 않는다.
- 예시 예상: 호출당 입력2000/출력400토큰이면 총 **$0.0792**. 실제 사용량은 호출 전 알 수 없다.
- 비용 예약 상한: 호출당 **$0.0125 ×24 = $0.30**. 요청 UTF-8 JSON 최대11000바이트 + 프로토콜 여유512토큰, 출력 최대800토큰으로 제한한다. 단가 변화·세금·계정의 다른 사용료까지 포함한 결제 보증은 아니다. 실행 승인 시 가격과 계정 조건을 재확인한다.
- 실제 준비물은 3343~6294바이트/요청이며, 모든 모델 답은 null/not_run이다. 정확한 system/input/schema와 각각의 해시를 [requests.json](llm-prepared-v1/requests.json)에 저장했다.
- 작성한 원인 가설과 실제 관측이 다른 사례도 있다. 고정 라벨 일치를 실제 정확도라고 부르지 않고, 반박/보류의 타당성은 독립 사람 검토로 남긴다.

## 지금 실행할 수 있는 무료 준비

```bash
python scripts/evaluate_queryscope_llm.py --suite queryscope-v3 --output work/new-preparation-v3
```

API 키를 읽거나 공급자를 생성하지 않는다. 입력·승인 템플릿(approved=false)·빈 인간 검토표를 만든다. 테스트 대역은 pytest 임시 폴더에서만 실행됐으며 공개 결과 파일에는 포함하지 않았다.

## 별도 승인 후의 실행 방법 (이번에는 실행하지 않음)

v2 준비물은 별도로 보존한다. v2와 v3를 합쳐48회로 승인된 것은 아니며 둘 다 미승인이다. 승인 파일의 suite도 `queryscope-v3`와 일치해야 한다.

1. 위 준비물과 기준을 검토하고 이 모델·24회·$0.30에 대한 사용자 승인을 받는다.
2. 승인 담당자가 템플릿을 별도 파일로 복사해 `approved=true`, `approved_by`를 채운다. 현재 준비물 SHA와 모델·호출 수·상한이 일치해야 한다. API 키는 서버 환경변수로만 설정한다.
3. 새로운 결과 디렉터리로 다음 명령을 사용한다.

```bash
python scripts/evaluate_queryscope_llm.py --live \
  --prepared docs/verification/queryscope-v3/llm-prepared-v1 \
  --approval work/explicit-user-approval.json \
  --output work/v3-actual-api-run
```

승인 파일 누락/불일치·준비물 변경·기존 출력·사용한 준비물의 재실행은 거절한다. 실행을 시작하면 준비물 해시를 키로 한 `work/llm-campaigns/<해시>/execution-claim.json`과 예산 원장이 남으며 오류/중단 후 자동 재개하지 않는다. 같은 체크아웃에서 준비물·출력 폴더를 복사해도 동일 캠페인은 다시 시작할 수 없다. 이 원장을 보존해야 하며 계정 전체나 다른 체크아웃까지 강제하는 서버 예산은 아니다. 요청 전에 예약하고, 실패도 한도를 소모한다. 원응답을 평가보다 먼저 저장하고 API 오류는 모델 보류로 세지 않는다. 부분 실행은 complete=false로 남는다. 잔여 호출 재승인은 실제 원장 확인 후 별도 계획이 필요하다.

완료 후에도 독립 의미 평가가 없으면 해당 축은 완료로 표시하지 않는다. 기존 결과를 덮어쓰거나 테스트 응답으로 빈 모델 결과를 채우지 않는다.
