# QueryScope v3: 정상 형태소 분석과 실제 누락 구분

2026-10-27 한국 시각. 현재 main `e8f967c`의 코드·v1/v2 원자료·CI·데모 구성을 확인하고 이어서 보완했다. 기존 main은 이미 v2를 포함했다. 과거 실제 API24회와 v1/v2 원자료는 변경하지 않았다. [보존 해시](preservation.json), [v2 동일 재현](v2-reproduction.json).

## 사전 고정과 범위

Codex 작성 합성16상품·24질의·정답·프로토콜을 `2e7ec2c`에 고정하고 검색 코드는 `f388b34`에서 측정했다. [manifest](manifest.json), [프로토콜](PROTOCOL.md), [정답](cases.json), [판정 기준](rubric.json), [전체 원시 결과](run-v1/results.json). v1/v2는 이번 보완에 사용했으므로 개발자료이다. v3 점수를 확인한 뒤 검색 알고리즘을 다시 튜닝하지 않았다.

통짜 색인을 강제한 부분어 누락4개, 정상 상품명8개, 표기변형2개, 영한1개, 유의어1개, 불명4개, 근거부족2개, 범위밖2개이다. 복합어4개는 실제 고객 장애가 아닌 통제된 결함이다. 평가 전에 원문 존재·토큰 누락·검색0건·재구성분해 후 정답1위, 정상8개 정답1위를 검사해 12조건 모두 통과했다. 조건 실패 시 점수를 내지 않고 중단한다. 자연 발생 분해 오류 사례는 새 자료에 없으므로 n=0이다.

기존90상품과 전체제목·상품ID 중복0, 기존 개발질의와 문자열 중복0. 새 분석어휘78개 중19개(24.36%)가 기존과 겹친다. 접미표현·상품개념·한국어상품도메인·운영지식·작성자를 공유하며 독립적인 일반화 자료가 아니다. 의미 정답은 작성자의 의도이며 독립 인간 판정은 없다. 실제 고객 데이터로 표현하지 않는다.

## 실패 원인과 남긴 사례

- **휴대용 배터리(V09, 개발):** 원문 단어 `휴대용`과 색인 `휴대`를 문자열로 비교해 정상 접미 분석을 누락으로 오판했다. 해당 단어의 실제 분석 토큰 집합이 문서 토큰에 포함되는지 비교하도록 수정했다. 잘못된 복합어 검색 신호가 사라지면서 밀려났던 유의어 원칙 문서가 복구됐다. 빈 분석 토큰은 누락 신호를 만들지 않는다. 특정 질의·정답표를 검색 코드에 넣지 않았다.
- **microscope(T15, 새):** 상품 검색이0건이면 상위 상품명과 문자 체계를 비교하는 관측이 발동하지 않는다. 실제 신호/추가 검색어 목록이 비었고, 기본 질의·관찰 문장 검색이 K012/K002/K013을 선택해 K007/K010을 top3에 넣지 못했다. 질의 분석 단계의 신호 부재와 지식 검색의 의미 관계 부족이 함께 남은 실패이다. 결과를 본 뒤 관련 키워드를 추가하거나 정답을 고치지 않았다.
- **팔래트·파스탤·microscope·박자기(T13–T16):** 원인 원칙 검색과 실제 상품 검색 복구는 별개이다. 통제된 복합어 수정만으로 이 네 순위 실패는 해결되지 않았다. 자동 의미 연결은 구현·검증하지 않았다.
- **멀티텝·악세사리·피펫트(V10–V12):** 기존 작성 분해 오류 가설의 구성타당성 문제는 유지한다. 앞의 두 개는 단일 토큰이고 피펫트는 이미 정답1위이다. 기존 고정 정답을 바꿔 점수를 높이지 않았으며 0/3 그대로이다.
- **차단제(V15), 크림(H11):** 정상 검색·작성 가설의 불확실성이 남아 있다. 새 모델 진단/보류와 독립 인간 검토 없이는 원인을 확정할 수 없다.
- **카페트·초콜렛·워시:** v2의 수동 표준형 연결·재구성분해를 같은 조건으로 다시 실행했다. 0.8262→1 / 0.4582→0.9832 / 0→1, 기존36+개발20 게이트와 결합 결과가 모두 과거와 동일하다. 초콜렛 선물의 무관한 향초 P105는 여전히 남는다. 선물 토큰만 공유하는 결과를 무조건 제거하면 다른 질의의 유효한 부분일치를 잃을 수 있어 근거 없이 필터를 추가하지 않았다.
- **과거 인용·복합어·원인 분류:** 원문 어미 변경/제목 인용, `[티슈,티슈]` 재구성 불가 후보, 백팩 원인 분류 오류는 원응답을 유지했다. 같은24응답의 검증 결과는 인용·형식 통과6/보류12/차단6으로 동일하다. 형식 검사 통과는 의미 정확도 증명이 아니다.

## 설명을 평가하는 다섯 축

| 축 | 자동으로 확인하는 범위 | 남은 판단 |
|---|---|---|
| 원인 분류 | 작성 계열 일치, supported/abstain/invalid 구분 | 실제 원인과 보류 이유의 충분성은 인간 검토 |
| 인용 추적 | 제공 본문·연속 발췌의 일치와 원문 위치 | 원문 존재가 의미 지지는 아님 |
| 의미적 지지 | `requires_human_review` 표시 | 관찰→인용원칙→원인 연결과 대안 설명, 독립 인간 평가 미완료 |
| 수정 구조 | 중복·재구성·공백·보류시 패치 금지 | 의미적 관계가 적절한지는 인간 검토 |
| 실제 검색 효과 | 격리 엔진의 전후 순위와 전체 회귀 | 평가셋 밖 효과는 미확인 |

실제 LLM24회 입력은 준비만 했다. 답은 모두 null/not_run, [사람 검토표](llm-prepared-v1/human-review.json)는 pending이다. 정상2·불명1·부족1·범위밖2, 원인사례6을 각 힌트/무힌트로 비교한다. 진단·보류·잘못된 패치·API 오류를 분리하고 테스트 대역/이전 응답을 새 생성으로 세지 않는다. [미승인 비용·실행 계획](PAID-EVALUATION-PROPOSAL.md).
