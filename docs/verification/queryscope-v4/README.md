# QueryScope v4: 원응답 보존과 런타임 적용 검사

2026-10-28 후속 검증. **새 API 호출0회·새 모델 응답0건**이며, v3의 실제24응답을 원래 입력으로 다시 검사했습니다. 최초 판정과 원응답은 보존하고 새 검사를 별도로 기록했습니다. 바뀐 입력48건은 준비만 했으며 `model_answer=null`, `generation_status=not_run`입니다. [전체 원자료](run-v1/audit.json).

## 범위와 결과

v3 자료를 확인한 뒤 보완했으므로 이제 개발 자료입니다. 기존 v1/v2/v3 자료159파일은 기준 커밋 `f7441a0ccadc6f35bee43d686f0989a5d1004c90` 대비 모두 보존했습니다([SHA-256 대조](preservation.json)). 기존 승인·24회 예산·과거 캠페인 준비 및 실행 경로는 변경하지 않았습니다.

| 측정 | 최초 v3 → v4 후속 검사 | 읽는 방법 |
|---|---|---|
| 동일24응답: 통과 / 보류 / 차단 | **7 / 9 / 8 → 6 / 9 / 9** | 새 생성 결과나 의미적 정답 수가 아님 |
| 추가 차단 | **1응답** | T15 `microscope` 힌트 조건, `canonical_not_in_index` |
| 후속 게이트 측정 | **6후보: 4응답 채택·2응답 기각** | 채택은 고유2질의 `팔래트`·`파스탤`, 각 표적 nDCG0→1 |
| 각 후보의 회귀 대조 | 기록된 하락0건 | 정답 있는 개발16질의와 기존36질의의 개별 적용; 결합·실제 고객 성능은 미확인 |
| 개발8개 계열의 무힌트 근거 hit@3 | **7/8 → 8/8** | 일반 원칙 검색이며 모델의 원인 진단·상품 검색 개선이 아님 |
| 같은 계열의 힌트 근거 hit@3 | **8/8 → 8/8** | 개선 없음 |
| 새 런타임 입력 준비 | **24질의×2조건=48건**, 답0건 | 최대7,444바이트, 전부 기존11,000바이트 한도 이내 |
| 독립 인간 의미 검토 | **24건 pending** | AI 검토 자료를 사람 판정으로 계산하지 않음 |

없는 대표어 `마이크로스코프`는 원래 T15 힌트 응답에서 형식·인용 검사를 통과했지만 검색 효과가 없었습니다. 새 검사는 이를 게이트 전에 차단합니다. T16 `박자기`의 `박자` 후보2응답은 해당 평가 엔진의 실제 토큰 조건을 통과해도 효과가0이므로 게이트에서 기각됩니다. 토큰 존재나 자모 유사성을 의미적 동등성으로 승인하지 않습니다. 기존8건의 인용 차단은 그대로 유지하며 원응답을 고쳐 성공으로 바꾸지 않았습니다.

## 구현과 원자료 연결

- **지식 인용 허용 목록:** `runtime_contract.py`가 실제 검색한 `KnowledgeDoc`의 ID·본문만 전달합니다. 상품ID·검색 결과·분석 토큰·관찰 후보는 인용 출처가 아닙니다. 검색 건수만으로 정상·관련성을 확정하지 않습니다.
- **적용 전 검사:** 기존 엄격한 스키마·원문 인용 검사를 먼저 실행한 뒤 대표어의 실제 색인 존재, 복합어 전체의 통짜 토큰 존재, 질의와 수정 대상의 관계를 검사합니다. 실패 시 `invalid`와 구체적 이유를 남기고 실행 가능한 처방을 제거합니다. 원응답은 따로 보존합니다.
- **설명 기반 관찰:** 질의 검색이0건일 때 사용자의 설명으로 제한된 상품 후보를 찾습니다. 최대2개를 `semantic_equivalence=unverified`로 표시하며, 문자 체계 차이가 있으면 기존 일반 원칙 검색을 보완합니다. 특정 질의·정답 대응을 검색 코드에 넣지 않았습니다.
- **과거 재현 유지:** 새 계약 표시가 있는 일반 런타임만 새 지침·검사를 사용합니다. 표시 없는 v2/v3 준비 요청의 payload 바이트가 그대로임을 검사합니다. 과거 캠페인의 원프롬프트·원판정은 별도입니다.
- **사후 분석의 출처 검증:** 원본 파일 해시, 고정된 준비 입력과 해시, 사례·조건24쌍, 원응답과 저장된 생성 결과, 모델·고유 응답ID의 연결을 대조합니다. 별도 AI 코드 검토에서 발견한 출처 연결 검증 누락을 수정하고 변조 회귀5개를 추가했습니다. 문맥·중복 사례쌍·원응답·준비 해시·응답ID 변조는 결과를 쓰기 전에 중단합니다.

원인·인용 추적·의미 지지·수정 구조·검색 효과는 나누어 확인합니다. 의미 지지는 계속 `requires_human_review`입니다. [AI 사전 검토](AI-REVIEW.md)는24응답의 관찰과 질문을 정리한 자료이며, [사람 검토 안내](HUMAN-REVIEW-GUIDE.md)를 따라 실제 검토자가 직접 판단해야 합니다. [원래 사람 검토표](../queryscope-v3/actual-api-human-review.json)의 사람 필드는 pending/null 상태입니다.

## 재현

Python3.11 또는3.12에서 저장소 루트 기준입니다. 평가 출력에는 존재하지 않는 새 폴더를 사용합니다.

```bash
pip install -e '.[api,mcp,dev,scale]'
python -m pytest -q
clinic baseline
python scripts/evaluate_queryscope_runtime.py --output work/reproduction-v4
python scripts/export_queryscope_runtime.py --input work/reproduction-v4/audit.json --output work/review-v4.json
python -m searchclinic.api.explanation_api
# http://127.0.0.1:8000/demo/review-v4.html
```

`evaluate_queryscope_runtime.py`는 모델 공급자를 만들지 않습니다. 기본 원본은 `docs/verification/queryscope-v3/actual-api-v1/results.json`입니다. 원본 연결 검증이 실패하거나 출력 폴더가 이미 있으면 중단합니다. 생성된 `audit.json`은 같은24응답의 사후 검사와 새48입력 준비를 구분하며, 정적 화면용 export는 원자료와 다른 경로에 씁니다. 과거 [v3 재현](../queryscope-v3/README.md), [실제 API 실행 기록](../queryscope-v3/ACTUAL-API.md), [v2 기록](../queryscope-v2/README.md)도 보존했습니다.

## 남은 한계

새 프롬프트로 실제 모델을 다시 호출하지 않아 상품ID 인용·잘못된 보류 계약·원인 혼동이 생성 단계에서 줄었는지는 알 수 없습니다. 8/8은 이미 본 개발 자료의 근거 검색 수치이며 독립 평가나 진단 정확도가 아닙니다. 없는 대표어와 무관한 대상은 기계적으로 차단해도 의미가 틀린 색인 토큰 후보는 남을 수 있습니다. T16의 효과 없는 후보와 기존 정상 검색의 상태·인용 계약 실패도 검토 대상입니다.

독립 인간 의미·정답 판정24건, 자연 발생 분해 오류의 새 평가, 실제 채용·고객 데이터 성능, 평가셋 밖 회귀와 장기 운영은 미완료입니다. 설명·인용·구조 통과나 유한한 게이트의 하락0건을 이 한계의 해소로 표현하지 않습니다.
