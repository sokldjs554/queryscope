# 실제 v3 응답 24건: 사람 검토 안내

이 문서는 **AI가 준비한 검토 자료**입니다. 사람의 독립적인 의미 평가를 수행한 결과가 아닙니다. 실제 검토자의 이름·독립성 선언·점수·판정은 아직 없으며 원래 사람 검토 기록은 pending 상태입니다. 검토자는 아래 안내와 AI 메모를 참고하되 실제 입력과 원응답을 직접 확인하고 판단 이유를 기록해야 합니다.

대상은 저장된 v3 실제 API 응답 24건(12사례 × `no_hint`/`hint`)입니다. `queryscope-v4`는 후속 자료의 위치이며 새 모델 응답을 뜻하지 않습니다. [v4 재검사](run-v1/audit.json)는 같은 응답에 새 적용 검사를 수행한 별도 기록입니다. 이 검토 자료의 과거 효과 수치는 v3 최초 판정과 이차 가상 적용을 구분해 읽습니다.

## 다섯 축을 따로 판단하기

각 축에 ‘충분 / 불충분 / 불확실’, ‘적절 / 부적절 / 불확실’ 등 판단을 적고 근거 필드를 연결합니다. 인용하지 않았거나 패치가 없으면 해당 축에 ‘해당 없음’과 이유를 적을 수 있습니다. 이는 검토 메모용 권장 표기이며 기존 평가 기준이나 자동 점수를 바꾸는 규칙이 아닙니다.

| 축 | 검토 질문과 확인 자료 |
|---|---|
| 원인 근거의 충분성 | 질의별 토큰·검색 결과·상품 원문과 색인 비교가 이 원인을 충분히 뒷받침합니까? 다른 원인을 배제할 근거가 있습니까? 일반 K 원칙·가족 라벨·힌트만으로 원인을 확정하지 않습니다. |
| 인용의 원문 일치 | 모든 인용이 해당 입력의 허용된 `context.documents[].body`에 연속 구절로 존재합니까? R 상품 ID는 관찰에는 있어도 당시 허용된 본문 인용 출처는 아닙니다. 표시 복원과 문구 변경을 구분하고 인용을 임의 수정하지 않습니다. |
| 의미적 지지 | 관찰 → 인용 원칙 → 결론의 연결이 타당합니까? 인용이 원문에 존재한다는 사실만으로 이번 원인을 지지하지는 않습니다. 비슷한 철자나 일반적 처방이 동의어 관계를 입증하지도 않습니다. |
| 수정안의 의미와 효과 | 대상 단어·대표어·분해가 의미상 맞고 실제 문제를 수정합니까? 형식 유효성, 최초 적용 자격, 표적 효과, 정답 있는 16질의와 기존 36질의 영향을 따로 기록합니다. `not_run`은 효과 미측정이며, 차단 후보의 가상 개선은 차단을 해소하지 않습니다. |
| 보류의 적절성 | 주어진 자료로 진단하거나 보류한 것이 적절합니까? 정상·불명·근거 부족·범위 밖은 기존 계약상 `abstain`과 무패치가 필요합니다. 설명·상태·검증 차단을 구분합니다. 실패 후보의 신중한 보류를 자동 오답으로 보지 않습니다. |

## 검토 순서와 완료 조건

1. 요청과 R의 실제 `context`를 먼저 읽습니다. 전체 카탈로그와 작성 qrels는 추가 검토 자료로 표시하고 생성 시점의 입력과 섞지 않습니다.
2. 원응답과 최초 검사 결과를 분리합니다. T05/T09 무힌트처럼 정상이라고 설명하면서 `supported`를 반환한 경우 상태와 설명을 각각 판단합니다.
3. 인용을 원문과 대조한 뒤 의미적 연결을 판단합니다. A의 기계 검사는 대조 자료이며 의미 판정이 아닙니다.
4. 패치의 정확한 단어와 카탈로그 대상을 확인하고, 실제 측정인지 가상 적용인지·최초 자격이 있는지 확인합니다. 형식 통과나 측정된 하락 0건을 의미 검증으로 해석하지 않습니다.
5. 사례·조건별로 다섯 축의 이유와 원자료 위치를 적습니다. 자료가 부족하면 빠진 증거를 구체적으로 씁니다. AI 메모나 작성 가족 가설을 답으로 그대로 복사하지 않습니다.
6. 실제 검토자만 이름·검토일·독립성 여부를 사실대로 기록합니다. 이 AI 자료를 열람했다면 공개하고, 빈 필드만 보고 독립성이 확보됐다고 가정하지 않습니다. H에는 인용 일치·측정 효과의 별도 필드가 없으므로 해당 내용은 첨부 검토 메모에 남깁니다.

검토자·검토일·사례별 이유가 실제로 기록되기 전에는 사람 평가가 완료된 것이 아닙니다. 새 검사로 얻은 판정도 최초 기록과 구분하며, 원응답과 기계 기록은 보존합니다.
